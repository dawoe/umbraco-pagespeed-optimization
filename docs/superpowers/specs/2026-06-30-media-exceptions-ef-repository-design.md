# Design: MediaExceptions EF Core Table + Repository Pattern

**Date:** 2026-06-30  
**Branch:** feature/davew/persistence-setup  
**Status:** Approved

## Overview

Add a `PageSpeedOptimizer_MediaExceptions` database table via Entity Framework Core, with a repository pattern providing CRUD access. Interfaces live in the Core project; internal implementations live in the Infrastructure project. The table is created via an EF migration that runs automatically on application startup.

## Purpose

Allow the PageSpeed Optimizer to store per-media-item exceptions, overriding the global image quality and WebP settings for specific media items.

## NuGet Packages

Add to `Directory.Packages.props`:

- `Umbraco.Cms.Persistence.EFCore` — Umbraco's EF Core integration (`AddUmbracoDbContext`, `IEFCoreScopeProvider`)
- `Microsoft.EntityFrameworkCore.Design` — dev-time only; required by the `dotnet ef` CLI to generate migrations

## Table Schema

**Table name:** `PageSpeedOptimizer_MediaExceptions`

| Column     | Type   | Constraints         |
|------------|--------|---------------------|
| Id         | GUID   | Primary key         |
| MediaKey   | GUID   | NOT NULL            |
| Quality    | INT    | NOT NULL            |
| ForceWebp  | BIT    | NOT NULL            |

## Component Designs

### Entity model — `MediaException` (Core)

A plain POCO with no EF or Umbraco attributes. EF mapping is done entirely via fluent API in the DbContext.

```csharp
public sealed class MediaException
{
    public Guid Id { get; set; }
    public Guid MediaKey { get; set; }
    public int Quality { get; set; }
    public bool ForceWebp { get; set; }
}
```

### Repository interface — `IMediaExceptionRepository` (Core)

All methods are async with an optional `CancellationToken`.

```csharp
public interface IMediaExceptionRepository
{
    Task<MediaException?> GetAsync(Guid id, CancellationToken ct = default);
    Task<IEnumerable<MediaException>> GetAllAsync(CancellationToken ct = default);
    Task<MediaException> CreateAsync(MediaException entity, CancellationToken ct = default);
    Task<MediaException> UpdateAsync(MediaException entity, CancellationToken ct = default);
    Task DeleteAsync(Guid id, CancellationToken ct = default);
}
```

### DbContext — `PageSpeedOptimizerDbContext` (Infrastructure, internal)

- Inherits from `DbContext`
- Exposes `DbSet<MediaException> MediaExceptions`
- Overrides `OnModelCreating` to configure via fluent API:
  - Table name: `PageSpeedOptimizer_MediaExceptions`
  - Primary key: `Id`
  - Column names match property names exactly
  - `MediaKey`, `Quality`, `ForceWebp` marked as required (non-nullable)

### Repository implementation — `MediaExceptionRepository` (Infrastructure, internal)

- Implements `IMediaExceptionRepository`
- Constructor takes `IEFCoreScopeProvider<PageSpeedOptimizerDbContext>`
- All operations wrapped in `using var scope = _scopeProvider.CreateScope()` + `ExecuteWithContextAsync`
- `Create`: adds entity, saves, returns entity
- `Update`: attaches/updates entity, saves, returns entity
- `Delete`: finds by id, removes, saves (no-ops if not found)
- `Get`: finds by id, returns null if not found
- `GetAll`: returns all rows as `IEnumerable<MediaException>`

### Migration runner — `RunMediaExceptionsMigration` (Infrastructure, internal)

- Implements `INotificationAsyncHandler<UmbracoApplicationStartedNotification>`
- Injects `PageSpeedOptimizerDbContext` directly
- Calls `await _dbContext.Database.MigrateAsync(cancellationToken)` on startup
- Idempotent: EF tracks applied migrations in `__EFMigrationsHistory`

## Registration

Extend `UmbracoBuilderExtensions.cs` with a new private method `AddMediaExceptionPersistence()`, chained into the existing `AddPagespeedOptimizer()` call:

```csharp
public static IUmbracoBuilder AddPagespeedOptimizer(this IUmbracoBuilder builder) =>
    builder
        .LoadConfiguration()
        .AddStaticCache()
        .AddResponseCompression()
        .AddOptimizedImageUrlGenerator()
        .AddMediaExceptionPersistence();   // new
```

`AddMediaExceptionPersistence` registers:
1. `AddUmbracoDbContext<PageSpeedOptimizerDbContext>` with `shareUmbracoConnection: true`
2. `builder.Services.AddScoped<IMediaExceptionRepository, MediaExceptionRepository>()`
3. `builder.AddNotificationAsyncHandler<UmbracoApplicationStartedNotification, RunMediaExceptionsMigration>()`

## Migration Generation (developer step)

After implementation, run from the Infrastructure project directory:

```bash
dotnet ef migrations add InitialCreate \
  --context PageSpeedOptimizerDbContext \
  --output-dir Persistence/Migrations \
  -s <path-to-startup-project>
```

Use `test-sites/Website-V17` as the startup project (it is the full Umbraco v17 site used for manual testing and has the runtime wiring needed by `dotnet ef`).

## Startup Migration Flow

```
App starts
  → UmbracoApplicationStartedNotification fired
  → RunMediaExceptionsMigration.HandleAsync()
  → PageSpeedOptimizerDbContext.Database.MigrateAsync()
  → EF applies pending migrations
  → PageSpeedOptimizer_MediaExceptions table exists
```

## Error Handling

- Migration failures on startup will surface as unhandled exceptions, preventing the app from starting — this is intentional (fail-fast on schema issues).
- Repository `Delete` on a non-existent id is a silent no-op.
- Repository `Update` on a non-existent id will throw an EF exception (caller's responsibility to call `Get` first if needed).

## Testing Notes

- Repository integration tests are out of scope for this spec (would require a running database).
- Unit tests for the notification handler can mock `PageSpeedOptimizerDbContext.Database` if needed.
- The `IMediaExceptionRepository` interface makes it easy to mock in higher-level tests.
